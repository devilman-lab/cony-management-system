## v1.2 での是正（実データ検証により判明）

実データを流したことで、設計と実データの食い違いを2件検出し是正した。詳細は `docs/06-外部データ検証レポート.md`。

1. **受注明細の種別** — 設計は `同梱商品` としていたが、実データは `内訳商品`。また `非商品`（クーポン等）が未定義だった。このままでは取込が全件エラーで止まる状態だった
2. **倉庫名** — 初期データ2件が実データと不一致（`交換・EC` → `交換・修理`、`補正下着他` → `美整体直販`）

## 設計上の確定事項

貴社より 2026/09/02 にご回答をいただき確定した事項。

1. **引当解除** — 出荷一覧からの削除は引当が外れて有効在庫が戻る。実在庫は不変
2. **セット商品** — セット在庫は持たず、構成商品それぞれの在庫から引き落とす
3. **販売カテゴリー** — マスタ登録して選択する形式（取引先ごとの自由入力は行わない）

## 開発の3部構成

| 部 | 目的 | 完了条件 |
|---|---|---|
| 第1部 基盤・日次オペレーション | 作業4名が楽楽販売を開かずに1日の業務を完了できる | 実データ1日分を本システムのみで処理し、物流センターで同じ帳票が一括出力できる |
| 第2部 金額系・月次サイクル | 1回の月次締めが本システムで完走する | 1締め分を並走で流し、請求書・売掛残高・入金消込・支払が現行と一致する |
| 第3部 連携・自動化・分析 | 手作業を削減し移行を完了、楽楽販売の契約を終了できる | 通販受注の手入力ゼロ、締め後1営業日で月次実績が出る |

**データベース設計は分割しない。** 第2部・第3部の要件が第1部のテーブル構造を制約するため、65テーブルすべてを最初に一度で確定させている。

## SQL の適用手順

```
psql -h <host> -p <port> -U <user> -d <database> -v ON_ERROR_STOP=1 -f docs/02-schema.sql
psql -h <host> -p <port> -U <user> -d <database> -v ON_ERROR_STOP=1 -f docs/03-seed-data.sql
psql -h <host> -p <port> -U <user> -d <database> -v ON_ERROR_STOP=1 -f docs/07-verify-objects.sql
psql -h <host> -p <port> -U <user> -d <database> -v ON_ERROR_STOP=1 -f docs/04-schema-tests.sql
```

- `02-schema.sql` は冒頭で `DROP SCHEMA IF EXISTS cony CASCADE` を実行する。既存データがある環境では実行しないこと
- `04-schema-tests.sql` はテスト用データを投入するため、**空のデータベースでのみ**実行すること。`07` は必ず `04` より前に流す
- クライアント側の文字コードは UTF-8 とすること（`PGCLIENTENCODING=UTF8`）
- `02` `03` `04` `07` は psql 専用コマンドを含まないため、Navicat / pgAdmin でも実行できる。手順は `docs/00-検証手順.md`
