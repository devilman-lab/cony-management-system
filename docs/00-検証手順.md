# データベースの検証手順（Navicat）

第1段階の成果物を、実際に構築して確認するための手順です。

---

## 0. その前に ― Navicat だけでは動きません

**Navicat はデータベースに接続するための道具（クライアント）で、データベース本体は含まれていません。** 先に PostgreSQL 本体をインストールする必要があります。

| 必要なもの | 入手先 | 備考 |
|---|---|---|
| PostgreSQL | https://www.postgresql.org/download/windows/ | EDB のインストーラ。無償 |
| Navicat | 既にご用意 | Premium / for PostgreSQL のどちらでも可 |

インストール時に設定する `postgres` ユーザーのパスワードは控えておいてください。ポートは既定の 5432 のままで構いません。

### バージョンについて

**動作要件は PostgreSQL 12 以上です。** 生成列（`GENERATED ... STORED`）が最も新しい機能で、それ以外はすべて古くからある構文です。16／17 でしか使えない構文（`MERGE`・`ANY_VALUE`・`JSON_TABLE`・`NULLS NOT DISTINCT` 等）は一切使っていません。

| 用途 | 15 系 | 17 系 |
|---|---|---|
| 今回の動作確認 | 問題なし | 問題なし |
| 本番のクラウドサーバー | 動作はするが、サポート期限が2027年11月と近い | **推奨**（2029年11月まで） |

**手元での確認は 15.2 などでも構いません。** 本番サーバーだけ 17 でご準備いただければ十分です（後から移行することも可能です）。

なお PostgreSQL 15 から `public` スキーマの権限仕様が変わりましたが、本システムは専用の `cony` スキーマを作ってその中に全て置くため、影響を受けません。

## 1. データベースを作る

Navicat で PostgreSQL に接続し、新しいデータベースを1つ作ります。

| 項目 | 値 |
|---|---|
| データベース名 | `cony_dev` |
| エンコーディング | `UTF8` |
| 照合順序 | 既定のまま |

`02-schema.sql` は冒頭で `DROP SCHEMA IF EXISTS cony CASCADE` を実行します。**既存データのあるデータベースでは絶対に実行しないでください。** 必ず新規のデータベースで行ってください。

---

## 2. SQL を順番に流す

Navicat の「クエリ」→「新規クエリ」を開き、ファイルの中身を貼り付けて実行します。**必ずこの順番で、1ファイルずつ**実行してください。

| 順 | ファイル | 内容 | 想定時間 |
|---|---|---|---|
| 1 | `docs/02-schema.sql` | テーブル70・関数8・トリガの作成 | 数秒 |
| 2 | `docs/03-seed-data.sql` | 区分値・権限・倉庫・システム設定・取込テンプレートの登録 | 数秒 |
| 3 | `docs/07-verify-objects.sql` | **構築結果の確認（4つの表が出ます）** | 即時 |
| 4 | `docs/04-schema-tests.sql` | 業務ルールの受入テスト49項目 | 数秒 |

### 実行時の注意

**① `$$` を含むブロックについて**

`02-schema.sql` と `04-schema-tests.sql` には `DO $$ ... END $$;` という書き方が出てきます。これは PostgreSQL の正式な記法ですが、ツールによっては途中の `;` で文を切ってしまい、エラーになることがあります。

Navicat でエラーが出た場合は、クエリエディタの設定で区切り文字の扱いを確認するか、PostgreSQL に付属の `psql` で実行してください。

```
psql -h localhost -U postgres -d cony_dev -v ON_ERROR_STOP=1 -f docs/02-schema.sql
```

正しく動いたかどうかは、手順3の確認クエリで「更新日時トリガ」の判定を見れば分かります。ここが `★NG` で 0 件になっていたら、`$$` の解釈に失敗しています。

**② 文字コード**

すべての SQL ファイルは UTF-8（BOM なし）です。Navicat で開く際に文字化けする場合は、接続の詳細設定でエンコーディングを UTF-8 にしてください。

**③ `05-import-validation.sql` について**

このファイルだけは `\copy` という psql 専用の命令を使っているため、**Navicat では実行できません**。CSV を実際に読み込んで検証するためのもので、スキーマの確認には不要です。実行される場合は psql をお使いください。

## 3. 何を見れば「正しい」と言えるか

### 手順3（`07-verify-objects.sql`）で出る4つの表

| # | 表 | 見るところ |
|---|---|---|
| 1 | 構造・整合性・初期データ・規模 | **「判定」列がすべて OK** であること |
| 2 | 業務ルールが制約として入っているか | 14件すべて OK であること |
| 3 | 一意制約（二重登録の防止） | 6件すべて OK であること |
| 4 | テーブル一覧 | 70件。Navicat 左ペインの一覧と一致すること |

1つ目の表で期待している値は次のとおりです。

| 区分 | 項目 | 期待 |
|---|---|---|
| 構造 | テーブル | 70 |
| 構造 | ドメイン | 3 |
| 構造 | 関数 | 8 |
| 構造 | 生成列（有効在庫・引当対象・ロイヤリティ適用優先度） | 3 |
| 整合性 | 更新日時トリガ | updated_at を持つテーブル数と一致 |
| 整合性 | 追記専用トリガ | 2 |
| 初期データ | 区分カテゴリー／区分値 | 23／55 |
| 初期データ | 販売カテゴリー／ロール／権限／倉庫 | 3／4／151／4 |
| 初期データ | 採番ルール／システム設定 | 11／24 |
| 初期データ | 取込テンプレート／その列定義 | 4／101 |
| 規模 | 外部キー／CHECK／インデックス | 200以上／40以上／130以上 |

### 手順4（`04-schema-tests.sql`）

Navicat の「メッセージ」タブに `T01 OK ...` から順に通知が出ます。最後に次の表示が出れば全件合格です。

```
==================================================
  スキーマ受入テスト 全件合格
==================================================
```

途中で赤いエラー（`TF001`）が出たら、その番号のテストが失敗しています。テスト番号とメッセージをお知らせください。

**注意：** `04-schema-tests.sql` はテスト用のデータを投入します。実行後は件数が増えるため、`07-verify-objects.sql` は必ず**手順4の前**に実行してください。やり直す場合は、`02` からもう一度流し直せば元に戻ります。

## 4. 特に見ていただきたいテーブル

Navicat でテーブルの中身を開いて確認いただくと分かりやすい箇所です。

| テーブル | 見どころ |
|---|---|
| `system_settings` | 消費税の端数処理、送料の閾値、通販CSVの取込モードなどが、プログラムではなく**設定として外に出ている**ことが分かります |
| `import_templates` / `import_template_columns` | 販社4社のCSVの書式が**データとして登録されている**こと。5社目が増えてもここに足すだけです |
| `codes` / `code_categories` | 区分値がすべてマスタになっており、画面から追加できること |
| `stocks` | `qty_available`（有効在庫）が `qty_on_hand - qty_allocated` の**自動計算列**になっていること |
| `sales_order_lines` | `is_stock_target`（引当対象）が種別とSKUから**自動判定**されること |
| `numbering_rules` | 伝票番号の採番ルール |
| `permissions` / `role_permissions` | 原価・仕入単価・ロイヤリティが閲覧者に見えない設定 |

## 5. やり直すとき

**`04-schema-tests.sql` は続けて2回実行できません。** テスト用のデータを投入するため、2回目は一意制約に弾かれます。冒頭の T00 でこれを検知し、次のメッセージで止まります。

```
ERROR:  前回のテストデータが残っています（該当 8 件）。
        02-schema.sql から順に流し直してから、もう一度このファイルを実行してください。
```

途中でエラーが出て止まった場合も、データが中途半端に入った状態になります。

いずれの場合も、**`02-schema.sql` からもう一度流し直せば元に戻ります。**冒頭で `DROP SCHEMA IF EXISTS cony CASCADE` を実行するため、前回の内容はすべて消えてから作り直されます。

```
02-schema.sql → 03-seed-data.sql → 07-verify-objects.sql → 04-schema-tests.sql
```

## 6. うまくいかないときの連絡内容

次の3つをお知らせいただければ、こちらで原因を特定できます。

1. どのファイルの実行で止まったか
2. エラーメッセージの全文（`ERROR:` から始まる部分）
3. `07-verify-objects.sql` の1つ目の表のスクリーンショット
