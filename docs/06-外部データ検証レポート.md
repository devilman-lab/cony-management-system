## 3. 設計との突き合わせ

### 3-1. 是正した点 ― 受注明細の「種別」

設計（v1.1）は明細の種別を `商品／セット商品／同梱商品／販促品／送料／値引` の6値としていましたが、実データは `商品／セット商品／内訳商品／送料／非商品` の5値でした。

| 設計 v1.1 | 実データ | 対応 |
|---|---|---|
| 同梱商品 | **内訳商品** | 現場でお使いの名称に合わせ、`内訳商品` へ改称 |
| （定義なし） | **非商品** | クーポン等。追加 |
| 販促品・値引 | `商品` で数量マイナス | 自社入力用として定義は残す |

このまま第2段階に進んでいた場合、実データの取込がすべてエラーで止まっていました。

あわせて、種別ごとの扱いを次のように整理しています。

- 在庫の引当対象は `商品` と `内訳商品` のみ。列 `is_stock_target` としてデータベース側に持たせ、判定を各画面に書かせない
- `セット商品` の行は在庫を引き当てない（構成品である `内訳商品` の行から引き落とす）。9月2日にご回答いただいた方針そのままです
- `送料`・`非商品` は自社商品コードがなくても登録できる

### 3-2. 是正した点 ― 倉庫名

初期データの倉庫名2件が実データと違っていました。

| 修正前 | 修正後（実データ） |
|---|---|
| コニー倉庫(交換・EC) | **コニー倉庫(交換・修理)** |
| コニー倉庫(補正下着他) | **コニー倉庫(美整体直販)** |

### 3-3. 設計変更が不要だった点

| 実データの形 | 設計での受け止め方 |
|---|---|
| セット商品の下に内訳商品がぶら下がる | `parent_line_no` で親子を保持。CSVは並び順で親子を表すため、取込時に補完する |
| クーポン・割引が数量 −1 で入る | 数量は負数を許容する型（`qty_num`）で定義済み |
| 送料の行が商品と同じ並びに入る | 明細の種別で区別し、引当対象から外す |
| 同じ受注番号が再度届く | `(チャネル × 受注番号)` の一意制約で二重計上を防止 |
| 同梱がある | 出荷どうしの自己参照で表現。`同梱元` 側の列を追加 |
| 備考欄に改行が入る | CSVの引用符付き改行として正しく読み込める |

### 3-4. 判明した確認事項

**セット商品の親子は、明細番号の並びでは決まりません。** 受注 `297847-20260831-0327001253` は、明細番号が 1（セット商品）→ 3（内訳商品）→ 4（内訳商品）→ 2（非商品）の順にファイルへ出力されていました。したがって取込処理は、明細番号順ではなく **ファイル内の出現順** で親子を決める必要があります。この仕様で実装します。

### 判明した点

**① JANコードが指数表記に壊れています**

| 販社 | JAN | 状態 |
|---|---:|---|
| ビックカメラ | 11件中 **11件が破損** | `4.57349E+12`（本来は13桁） |
| ラベルヴィ | 5件中 **5件が破損** | `2.00E+12` |
| 白鳩 | 4件中 0件 | 正常（末尾に半角空白あり。取込時に除去します） |

Excelで開いて保存した際に、13桁の数値が指数表記に変換されたものです。ビックカメラとラベルヴィは自社の商品コード列があるためJANを使わずに取り込めますが、**白鳩だけは商品コードの列がなくJANで引き当てるため、白鳩のファイルがExcel経由で保存されると取り込めなくなります**。白鳩のファイルは、Excelで開かずにそのままお渡しいただくか、開いた場合はJAN列を文字列として保存していただく必要があります。取込時に桁数を検査し、壊れている場合はエラーとしてお知らせします。

**② 単価をどの列から採るか**

| 販社 | 単価の候補 | 本システムでの採用（暫定） |
|---|---|---|
| ビックカメラ | 発注時単価 5,000／出荷時単価 4,991 | **出荷時単価** |
| ラベルヴィ | 卸値2,100／セール単価3,564／GLS単価4,000／発注金額2,138 | **発注金額 ÷ 発注バラ数** |
| 白鳩 | 上代6,500／下代2,345 | **下代** |
| コネクト | 発注単価 | 発注単価 |

ラベルヴィは、発注金額が「セール単価(税抜) × 掛率60%」を1個あたりで丸めてから数量を掛けた金額になっていました（例：3,564×60%＝2,138、4,876×60%×2＝5,852）。卸値の列とは一致しません。この理解で合っておりますでしょうか。

**③ ビックカメラの商品コードと商品名の不一致**

`受注*14324` は商品コードが `CS2426-0000-112` ですが、型番/商品名の列は `CS2426-0000-100 Fornez AURA` となっており、カラーの枝番が食い違っていました。取込は商品コードを優先しますが、この行の扱いをご確認ください。

**④ ビックカメラの「データ種別」**

11行のうち10行が `2`、最終行（受注*14330）のみ `11` で、この行だけ伝票No `75896054` が入っていました。種別によって扱いを変える必要があるか教えてください。現在はすべて同じ扱いで取り込みます。

## 5. 検証の実行手順

本レポートの内容は、頂戴したCSVを実際に読み込んで確認したものです。データベース上での取込は次の手順で再現できます。

```
powershell -ExecutionPolicy Bypass -File scripts\prepare-import.ps1 `
  -OmsCsv "..\要件\OS_beautyjapan_20260901_170556.csv" `
  -AmazonCsv "..\要件\2026AugMonthlyTransaction (1).csv" `
  -PartnerCsv "..\要件\追加\★ビックカメラ取り込み.csv","..\要件\追加\★ラベルヴィ取り込み.csv",
              "..\要件\追加\★白鳩取り込み.csv","..\要件\追加\コネクト_インポート.csv" `
  -OutDir .\work

psql -v ON_ERROR_STOP=1 -f docs/05-import-validation.sql
```

販社CSVについては、上記のスクリプトが列数の一致とJANの桁数を点検し、壊れている場合は警告を表示します。

`05-import-validation.sql` は V01〜V10 の検証を行い、1件でも失敗すると停止します。V10 では同じCSVをもう一度取り込んで件数が増えないこと（二重計上しないこと）まで確認します。

## 6. 貴社にご確認いただきたいこと

1. **通販CSVの位置づけ**（既にお伺いしている件）
   送り状番号・出荷予定日・伝票管理番号が入力済みで、最終ステータスも全件「処理済み」でした。**すでに出荷が済んだ実績データ** と理解して進めております。もし「これから出荷指示を出すためのデータ」としてもお使いになる場合は、設定を切り替えるだけで両対応できるようにしてあります。

2. **同梱の相手先**
   同梱元に指定されている受注番号が、このファイルには含まれていませんでした。別ファイルに出力されるのか、あるいは同梱された側は出力されないのか、運用を教えていただけますでしょうか。

3. **単価と住所のマスキング**
   金額が一律 1234 に置き換えられ、住所も市区町村までとなっていました。金額計算と住所の桁数まで含めて検証するため、可能でしたら実データに近いファイルを1本お預かりできますと助かります。難しい場合は、この形のままでも開発は進められます。

4. **送料の金額**
   「1回の出荷が30,000円以下の場合に送料を請求」というルールは伺っておりますが、**請求する送料の金額**を伺えておりません。暫定として0円で登録し、取引先ごとに設定できる形にしてあります。全社共通の金額か、取引先ごとに異なるかもあわせて教えていただけますでしょうか。

5. **白鳩のJANコード**（4-3 ①）
   白鳩のファイルは商品コード列がなくJANで引き当てます。Excelで開かずにお渡しいただけますでしょうか。

6. **ラベルヴィの単価**（4-3 ②）
   「発注金額 ÷ 発注バラ数」を単価として採用する理解で合っておりますでしょうか。

7. **ビックカメラの2点**（4-3 ③④）
   商品コードと商品名が食い違っている行の扱いと、「データ種別」（2 と 11）で処理を分ける必要があるかどうか。
