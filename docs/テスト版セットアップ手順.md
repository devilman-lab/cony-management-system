# 販売管理システム テスト版 セットアップ手順

第3段階（画面）のテスト版を、4名でお試しいただくための手順です。
Docker が入った PC またはサーバー 1 台で、画面・業務処理・データベースがまとめて動きます。

## 1. 用意するもの

| もの | 内容 |
|---|---|
| Docker Desktop（Windows／Mac）または Docker Engine（Linux） | 動作環境。https://www.docker.com/ |
| このリポジトリ一式 | `backend/` `frontend/` `docs/` `docker-compose.yml` |
| 空きポート | 既定は 3000 番（変更可） |

4名が別々の PC から使う場合は、社内 LAN で到達できる PC／サーバーで動かし、その IP アドレス（例 `http://192.168.1.20:3000`）を各自のブラウザで開きます。
社外から使う場合は VPN か、クラウドの VM（後述）でお願いします。**インターネットへそのまま公開しないでください**（受注データに購入者の氏名・住所が含まれます）。

## 2. 初回の起動

リポジトリの一番上のフォルダで、`.env` ファイルを作ります（`.env` はコミットされません）。

```
DB_PASSWORD=データベースのパスワード（任意の英数字）
JWT_SECRET=ログイン用の秘密鍵（32文字以上の英数字。下のコマンドで作れます）
WEB_PORT=3000
```

`JWT_SECRET` の生成例（Node.js がある PC で）:

```
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

続けて起動します。初回はイメージの作成に 5〜10 分かかります。

```
docker compose up -d --build
```

初回起動時にデータベースへ `docs/02-schema.sql`（テーブル 70 個）と `docs/03-seed-data.sql`（区分・権限・設定などの初期データ）が自動で入ります。
受注・在庫などの業務データは空の状態です。

## 3. 管理者のパスワードを設定する

初期データの管理者 `admin` はパスワード未設定です。次の 1 行で設定します。

```
docker compose exec api node dist/cli/set-user-password.js admin "決めたパスワード"
```

ブラウザで `http://localhost:3000`（別の PC からはその PC の IP アドレス）を開き、`admin` でログインします。

## 4. 利用者を 4 名登録する

ログイン後、左メニュー **マスタ ＞ ユーザー・権限** で「利用者を追加」。
ログインID・氏名・初期パスワード（10 文字以上）・役割を入れます。

| 役割 | できること |
|---|---|
| 管理者 | すべて（原価・利益も見える） |
| 作業者 | 受注・出荷・在庫・取込・マスタ |
| 経理 | 請求・入金・仕入・支払・分析 |
| 閲覧者 | 参照のみ |

役割ごとの権限は「役割と権限」タブで変えられます（原価・利益は「機微」と表示された項目です）。

## 5. お試しの流れ（おすすめ）

1. **マスタ**：取引先 → 納品先 → 商品・SKU → 得意先別商品（卸単価・上代）→ 販売担当（分類・区分・設定）
2. **入荷**：入荷登録で実在庫を作る
3. **引当在庫**：月の枠を販売カテゴリー×商品で登録（9/17 ご確認の「確保数」）
4. **受注**：受注入力 → 登録時に引当（枠から減り、実在庫を超えるとエラー）
5. **出荷**：出荷一覧で選んで「出荷確定して印刷」→ 実在庫が減り、納品書などの PDF がまとめて出る
6. **請求**：締め処理 → 請求書の確認・印刷
7. **CSV取込**：販社の発注 CSV を「確認だけ」→「取り込む」

画面右上の「ヘルプ」に各画面の説明があります。

## 6. 日々の操作

| したいこと | コマンド |
|---|---|
| 止める | `docker compose down` |
| 再開する | `docker compose up -d` |
| 画面・処理を更新する（修正版を受け取ったとき） | `docker compose up -d --build` |
| ログを見る | `docker compose logs -f api` |
| データを全部消してやり直す | `docker compose down -v` （← 業務データも添付も消えます） |

データはボリューム `db-data`（データベース）と `attachments`（添付ファイル）に残ります。`down` では消えず、`down -v` で消えます。

## 7. バックアップ

```
docker compose exec db pg_dump -U cony cony > backup_$(date +%Y%m%d).sql
```

添付ファイルは `docker compose cp api:/app/storage/attachments ./attachments_backup` で取り出せます。
どちらも購入者の個人情報を含みうるため、共有ドライブや「リンクを知っている全員」の場所には置かないでください。

## 8. クラウドで動かす場合

上と同じ手順が、Ubuntu の VM（さくら VPS、AWS Lightsail、ConoHa など月 1,000〜2,000 円程度）でそのまま使えます。
その場合は次の 2 点を追加でお願いします。

- ファイアウォールで 3000 番を **社内の固定 IP からだけ** 許可する
- HTTPS にする（Caddy などのリバースプロキシを前に置く。ご希望があればこちらで設定します）

## 9. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 画面が開かない | `docker compose ps` で 3 つ（db／api／web）が `running` か。`WEB_PORT` が他のソフトと重なっていないか |
| ログインできない | 手順 3 のパスワード設定を実行したか |
| PDF の日本語が出ない | api コンテナには Noto Sans CJK を同梱しています。自前のサーバーで動かすときは `PDF_FONT_PATH` を設定 |
| CSV 取込で「列数が合いません」 | 販社の書式が変わっています。ファイルをお送りください |
